# Travel Planning Kit

Use this skill when someone wants help building or improving a trip plan with this kit. Read the repository README and `docs/FORMAT.md` first. The executable schema is `travel_kit/schema.py`; the invented example shows a complete input.

## Work from the person's priorities

Establish dates, origin, group needs, budget scope, must-haves and pace. Use `templates/trip-brief.md`. Ask only for missing information that changes a decision. Preserve different preferences and unresolved questions instead of inventing consensus.

Keep actual travel details in a user-chosen private folder. Do not put real people, booking references, private messages or personal photos into public fixtures or Git history. Never use the invented demonstration as evidence about real destinations or rentals.

## Preserve the whole workflow

1. Adapt the reusable catalog and trip tags. Keep explicit additions/exclusions, quantities, assignees and morning-of checks. Do not replace the catalog with a tiny one-off packing list.
2. Build the plan's summary, status, day anchors and backups, open decisions with ownership/urgency, activities, preference answers and source notes. Record reasons, not just the chosen outcome.
3. Research rentals with `templates/rental-research.md`. Preserve all 22 table fields plus sleeping layout, relevant practical details, sauna, photo credits and ranking rationale. Keep shortlist, alternatives and rejected options.
4. Use exact/range/unknown quote types honestly. Record quoted dates, fee scope and check dates. Do not silently equate different stays or fabricate availability. Let the kit calculate exact splits.
5. Generate all four documents through the shared CLI or editor. Inspect the gallery and print layouts. Fix missing data deliberately rather than removing the affected workflow.
6. After the trip, capture what worked, what should change and what to carry forward.

## Research and actions

Browse for current prices, opening hours, availability or other changing facts when research is requested. Keep source links and check dates; label inference. The optional photo command runs only with URLs explicitly chosen for the task. It does not grant image reuse rights or guarantee a site's images can be collected.

Do not book, buy, send messages, submit forms, or publish a private plan without the user's applicable authorization. Preparing a plan does not imply those actions. Use the user's existing authorization when it does cover an action; do not add ritual approval steps.

The kit is a local planning tool, not a booking engine, live data service or integrated Google Docs uploader. Be precise about which actions have actually been performed. Save the editable JSON alongside outputs and leave clear instructions for reopening it.
